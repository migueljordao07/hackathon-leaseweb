# App-to-Infra PR Reality Guard

> For **platform and DevOps engineers reviewing AI-accelerated application pull requests**, we help **catch hidden cloud egress, NAT gateway, and logging cost explosions before merge** using **AI to connect application code diffs with declared cloud topology and validate amplification in a local replay harness**, reducing **surprise post-deploy cloud bills and manual PR review bottlenecks**.

**Proposed by:** Diogo (`diogo1`) · **Status:** Exploring
**Theme:** AI-assisted operations
**Date:** 20 November 2026

## 1. Problem and user

- **Who encounters this, and when?** A DevOps, SRE, or platform engineer reviewing high-volume application pull requests—increasingly generated by coding assistants (Copilot, Claude, Cursor)—that pass local unit tests yet interact poorly with production cloud networking and observability pricing.
- **What goes wrong today?** Application-level micro-changes trigger severe infrastructure bills that static IaC tools never see: flipping a logger to `DEBUG` or logging full HTTP payloads inside a hot path causes a sudden multi-thousand-dollar CloudWatch/Datadog ingestion spike, or adding an uncached external/object-storage fetch inside a private subnet without a VPC gateway endpoint silently routes terabytes through a per-GB NAT Gateway. Teams discover the root cause weeks later on an invoice.
- **Current workaround:** Manual senior-engineer PR review (which does not scale under AI PR volume), retrospective cloud billing alerts / CUR Athena queries after money is spent, or blunt post-incident log drops.
- **Evidence and source:** Multiple recurring Reddit threads on `r/devops` and `r/FinOps` document both halves of this collision: *"Anyone noticed AI PRs that ignore infrastructure and DevOps realities?"*, *"Anyone else seeing AI make DevOps/infra the bottleneck?"*, *"$10K logging bill from one line of code - rant about why we only find these logs when it's too late (and what we did about it)"*, and *"NAT Gateway is somehow 80% of our AWS bill, how are you all keeping this in check?"*. The FinOps Foundation 2026 survey cited in the [team briefing](../../ai-cloud-infrastructure-team-briefing.md) also highlights pre-deployment architecture costing as a practitioner priority. These threads document recurring community pain points, not measured demand for this exact tool; direct Reddit permalinks were retrieved via search redirects and remain to be verified in a browser.

## 2. Proposed solution and AI contribution

- **User workflow:** Submit a Git PR diff (application code + config) together with the repository's declared infrastructure topology (subnets, NAT gateway vs. VPC endpoints, log sink, egress allowlist) → AI identifies application changes that interact dangerously with topology/cost boundaries → a deterministic local replay harness executes the service before and after the PR under sample traffic → measure actual emitted log bytes and external/NAT-routed call counts → report verified findings, cost-driver sensitivity (with explicit transparent rate assumptions), and a bounded fix suggestion.
- **What AI adds:** Bridges the semantic gap between **application code diffs** (loops, log verbosity, payload serialization, SDK calls, retry multipliers) and **infrastructure topology** (private subnet lacking an S3 gateway endpoint, paid per-GB log collector, cross-AZ or non-EU egress), generating targeted replay scenarios and explaining *why* a one-line app edit creates an infrastructure bill bomb. Deterministic counters—not LLM guesses—measure the actual before/after byte and request amplification.
- **Simple baseline:** Static IaC cost estimation (`Infracost`-style `.tf` check, which reports `$0` on pure app diffs) plus a static grep/Semgrep rule flagging `LOG_LEVEL=DEBUG`.
- **Action boundary:** Read-only analysis on Git diffs and topology files; replay runs strictly inside a local sandboxed service with mocked outbound endpoints on the Linux VM. The tool comments/reports and proposes diffs; it never merges PRs, modifies cloud billing/networking, or executes arbitrary shell commands from PR content (untrusted PR diffs are treated as prompt-injection-risk input per OWASP guidance in the [team briefing](../../ai-cloud-infrastructure-team-briefing.md)).

## 3. Existing alternatives and difference

| Alternative or workaround | What it already solves | Our specific difference |
|---|---|---|
| [Infracost](https://www.infracost.io/docs/) | Estimates monthly cloud cost deltas from Terraform/OpenTofu diffs directly inside PRs. | Proposed: catches *application-code* cost and egress bombs (e.g., payload logging loops, uncached calls over NAT) where `.tf` files did not change at all. |
| [Semgrep](https://semgrep.dev/docs) | Fast static AST pattern matching for custom code rules in CI. | Proposed: reasons across both application code *and* the service's actual declared VPC/NAT/observability topology, then empirically measures byte amplification via replay. |
| Cloud billing alerts / [OpenCost](https://opencost.io/docs/faq/) | Measures spend and allocates costs once workloads are running in production. | Proposed: shifts detection left to pre-merge PR review and links measured amplification directly back to the offending commit lines. |

**Why would this user choose our approach?** Hypothesis: no single open-source tool currently joins application PR diffs with declared cloud topology and empirical local replay to catch "one-line code, $10K cloud bill" regressions before merge. Must prove clear value over simple Semgrep rules + manual review; differentiation remains a hypothesis.

## 4. Smallest working demo

**Demo story:** A developer opens an AI-generated feature PR on a backend service that passes every unit test and shows `$0.00` change in static IaC review, yet would multiply log ingestion by 20× and NAT Gateway egress by 10× in production.

1. **Before:** Show a small local Python API/worker service paired with a declared topology fixture (private subnet → NAT Gateway, no S3 VPC gateway endpoint, metered log sink). Present a realistic PR diff that (a) adds full request/response payload logging inside a middleware/loop and (b) adds an uncached object-store read per request. Show that unit tests pass and a static IaC diff reports zero cost change.
2. **Intervention:** Run App-to-Infra PR Reality Guard. The AI links the PR diff to the missing S3 VPC endpoint and metered log sink, selects/runs a deterministic 100-request local traffic replay against `main` vs. `PR`, and instruments actual emitted log bytes and outbound proxy-intercepted NAT bytes.
3. **After:** Display a PR-style review report with measured before/after metrics (exact log KB/100 req, NAT-routed KB/100 req, and clearly labeled illustrative unit-price projection), apply the suggested bounded patch (structured summary logs + response caching / VPC endpoint snippet), and re-run the replay to confirm log and egress counters return to baseline while functional tests stay green.

- **Must build:** (1) Sample service + topology fixture + 3 seeded PR diffs (debug/payload log bomb, NAT egress loop, benign feature PR); (2) Topology-aware AI diff analyzer with prompt-injection boundaries; (3) Local before/after replay & byte/egress metering runner with a clean PR-report view.
- **Out of scope today:** Live GitHub App OAuth hosting, live AWS CUR/CloudWatch API ingestion, multi-service distributed load testing, and guaranteed production dollar-bill accuracy (all cost projections must be labeled as unit-rate sensitivity estimates derived from measured byte ratios).
- **Success metric:** Proposed target: detect all 2 seeded cost-bomb PRs with exact diff line citations and measurable >5× byte/call amplification, pass the benign PR with zero false alarms, and verify amplification drops back to baseline after the fix. Not yet measured.
- **Failure case:** If the service fails to boot in replay or the model output lacks valid diff line references, emit `review_incomplete` rather than an `approved` check; ignore any instructions embedded inside PR comments or code strings.
- **Demo fallback:** Local Git repo with pre-staged PR branches and a clearly labeled replayed model response; the local HTTP proxy, log-byte meter, and before/after traffic replay always run live on the VM.

**Rough effort and split:** Medium relative effort. Suggested split: sample app + 3 PR branches; local egress/log metering proxy & replay runner; topology parser & AI analyzer; PR report UI; evaluation & pitch. Hardest integration: reliably running `base` vs. `head` commits side-by-side and capturing clean, reproducible log and outbound-egress byte deltas. Owners unassigned.
**Biggest blocker:** If static Semgrep rules catch the exact same demo PRs with less complexity, the AI contribution will look weak—the seeded PRs must demonstrate genuine cross-file code-plus-topology reasoning (e.g., an innocent-looking helper call that only becomes a NAT bomb because of the subnet route table).

Keep model API keys in `.env` outside Git. Avoid inventing opaque dollar savings; always display **measured bytes/requests per 100 calls** first, and show illustrative unit pricing as a transparent formula.

## 6. Fastest validation

- **Riskiest assumption:** AI cross-referencing application diffs against declared topology catches real cost/egress risks that simple static lint rules miss, without flooding developers with false positives on benign PRs.
- **Quick experiment:** Prepare 4 small PR diffs (payload logging in a loop, uncached private-subnet external fetch, retry multiplier on timeout, and a benign refactor) + 1 topology JSON. Compare a 5-rule static linter against the AI analyzer + local byte meter.
- **Continue if:** The tool flags the topology-dependent traps accurately, avoids flagging the benign PR, and the live byte meter produces dramatic, repeatable before/after numbers.
- **Simplify or park if:** Simple regex/Semgrep rules achieve identical results or the LLM cries wolf on benign PRs.
